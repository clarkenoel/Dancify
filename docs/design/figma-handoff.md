## Button purposes and existing runtime contracts

Use the existing frontend controllers and APIs. These are handoff mappings, not new React code.

| UI action | Runtime purpose |
| --- | --- |
| Choose video / Change video / Choose another | Open library or return to selection; choose a ready song and capture its active bundle before play. |
| Import video / Video URL | Open preparation form. URL creation uses `POST /songs/json`. |
| Upload file / Upload fallback | Select a local video using the browser file picker; multipart `POST /songs`. The upload field displays the selected filename. Upload changes acquisition only. |
| Prepare video / Prepare again | `POST /songs/{song_id}/preparations`; source kind is url or upload. |
| Preparation progress | Poll `GET /songs/{song_id}/preparations/{job_id}`; show actual stage updates rather than a fabricated percentage. |
| Retry preparation | Retry only a failed job with `POST /songs/{song_id}/preparations/{job_id}/retry`. |
| Enable camera | Request browser camera access and initialize the existing local camera tracker. Display camera failure with retry and keyboard fallback. |
| Play | Start the reference video and selected scoring mode. |
| Keyboard practice | Select `keyboard_practice`; use the existing gameplay key bindings and label its results as practice. |
| Pause / Resume | Pause or resume the reference video. Pause emits no judgments. |
| Restart / Restart video | During play, open confirmation first. Confirm resets playback and creates a fresh scoring epoch; cancel keeps the current attempt. Results restart begins a new attempt in its original mode. |
| Exit / Exit video | During play, open confirmation first. Confirm stops the current attempt, releases camera resources as appropriate, and returns to selection. |
| Menu / Main menu | Open the game menu or return to the main menu; leaving an active attempt uses confirmation. |
| Volume + / Volume − | Adjust the reference video's volume, clamped to its valid range. |
| Mute / Unmute | Toggle reference-video muted state; restore the previous volume on unmute. |
| See score | Show the completed result summary. The prototype menu shortcut is for reviewing this state; it must not invent a completed result mid-song. |
| Play history | Load saved per-song plays with `GET /songs/{song_id}/plays`. |
| Retry save | Retry the stored ResultOutbox payload with `POST /songs/{song_id}/plays`; preserve the same session ID and bundle ID. |
| Connect wearable / Reconnect / Cancel connection | Use WearableClient transport lifecycle; show disconnected, connecting, connected, or lost. These visual states do not claim real BLE transport is implemented. |
| Continue without wearable | Keep camera/keyboard gameplay available without a controller. Wearable never affects score. |

Failure copy is parameterized by the documented preparation error code: download_failed offers upload; unsupported_media requests browser-decodable video; timing_required requests audible music; tracking_failed requests cleaner solo footage and retains diagnostics; validation_failed prevents play; interrupted/internal offer retry. Retain an older ready bundle during replacement preparation.

## Gameplay and input behavior

- Reference and mirrored webcam viewports preserve 16:9, with letterboxing allowed. Timing rings and song progress sit on the reference. Current and next pictogram slots receive chart assets.
- Reference `<video>.currentTime` is the only scoring clock. Do not add an audio-sidecar clock.
- A static checkpoint occupies `start <= t < end`. The timing ring communicates approach/window progress; it does not claim an exact musical hit. No holds or exact-hit sparkles.
- Insufficient pose data returns null. Show **Step back into frame**, distinct from MISS; break combo without converting tracking loss into a zero score. The current single-person tracker reacquires automatically. Planned session identity pairing is outside this delivery.
- Camera results show star rating, accuracy, longest combo, and PERFECT / SUPER / GOOD / MISS breakdown. Practice results use a practice timing label and do not claim camera accuracy.
- Pending-result state retains the completed result in browser storage and retries that exact record.
- Keyboard arrows or Tab / Shift+Tab and wrist rotation navigate ordered focus. Enter or wrist press selects. Aqua outline marks focus; gold marks selection. Skip disabled controls, keep the focused row visible, and restore focus after a dialog. Escape cancels a confirmation.
- Connection recovery offers retry, another video, main menu, and continuing without wearable where applicable. Keyboard fallback remains available.
- No login, multiplayer, or cloud inference.
